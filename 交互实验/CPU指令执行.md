# CPU 指令执行模拟

一条指令从内存到执行，要经过取指、译码、执行与写回。这个实验用一个简化的累加器 CPU，把寄存器、内存与程序计数器同时展示出来，支持单步与自动运行。

## 指令集

| 指令 | 编码 | 语义 |
| --- | --- | --- |
| `LOAD addr` | `1 × 1000 + addr` | `ACC ← mem[addr]` |
| `STORE addr` | `2 × 1000 + addr` | `mem[addr] ← ACC` |
| `ADD addr` | `3 × 1000 + addr` | `ACC ← ACC + mem[addr]` |
| `SUB addr` | `4 × 1000 + addr` | `ACC ← ACC - mem[addr]` |
| `JMP addr` | `5 × 1000 + addr` | `PC ← addr` |
| `JZ addr` | `6 × 1000 + addr` | 若 `ACC = 0`，则 `PC ← addr` |
| `HLT` | `7000` | 停机 |

指令与数据放在同一片内存中，这是冯·诺依曼结构的直接体现。程序把 `LOAD 12` 编码为 `1012`，CPU 读取这个数字后，用高位的操作码判断“这是一条 LOAD”，用低位得到地址 12。

## 观察建议

1. 载入「累加 1…N」，单步执行，记录每次 `JZ` 时 `ACC` 的值。
2. 观察 `STORE` 之后内存单元格的变化，确认写回发生在执行阶段。
3. 切换到「倒数循环」，比较 `JMP` 与 `JZ` 对 `PC` 的不同影响。
4. 自动运行到 `HLT`，检查最终结果是否等于 $1 + 2 + \dots + 5 = 15$。

## 从指令到程序

一个循环由三部分组成：

- **初始化**：设置计数器与累加器。
- **循环体**：执行计算并更新计数器。
- **终止条件**：用 `JZ` 或比较指令跳出循环。

真实的 CPU 还会加入流水线、乱序执行、分支预测与缓存，但控制流的本质仍然是“修改 PC，取下一条指令”。

::: info 为什么先讲累加器架构
累加器架构的寄存器少、数据通路简单，适合理解取指—译码—执行的骨架。现代 RISC 处理器使用更多通用寄存器与 load/store 架构，但基本周期并未改变。
:::

## 思考题

1. `JZ 17` 与 `JMP 17` 的区别是什么？分别对应高级语言的哪种控制结构？
2. 如果把 `SUB 16` 改成 `ADD 16`，程序会发生什么？为什么？
3. 为什么指令和数据可以放在同一片内存中？这带来了什么安全隐患？
4. 真实 CPU 的流水线如何影响 `JMP` 之后的取指？
